# 联机与持久化设计

日期：2026-10-22。状态：拟议架构，尚未实现或完成承载验证。本文描述游戏需要满足的行为，不代表 Estella 已提供完整的账号、世界服务或分布式运行平台。

## 1. 目标与边界

共享身份、唯一星球地址、可持久化的家园、跨星球协作、主人离线后可访问，以及按活跃区域扩展服务。

全宇宙的参与者不受固定小队人数限制；每个实时区域仍有 CPU、带宽、存储及延迟预算。总容量随部署资源变化，局部容量必须压测。测试人数只是证据，不是“无限人数”证明。

## 2. 三种不同的分区

| 概念 | 作用 | 不能据此推断 |
| --- | --- | --- |
| 客户端地图区块 | 控制几何、纹理和实体加载/释放 | 已经实现服务器水平扩展 |
| 服务端模拟区域 | 为活跃实体分配权威模拟与同步 | 同一热点可以无限扩容 |
| 数据分区 | 按星球/区块组织保存与查询 | 每个区块都需要一个独立进程 |

原型可先用一个专用服务进程承载多个逻辑区域，验证接口和一致性后再扩为多工作进程。区域身份和全局实体身份从第一版分离，客户端不依赖具体服务器地址作为世界身份。

## 3. 服务职责建议

```text
游戏客户端
  ├─ 会话与访问入口：身份、连接、目的地路由
  ├─ 星图目录：地址、发现、归属、访问规则
  ├─ 区域模拟：移动、交互、建造、环境事件
  └─ 持久状态：库存、建筑、项目贡献、转移记录
```

初期可以在同一服务内实现这些职责，通过清晰数据边界避免过早拆成大量微服务。每个实体在任何时刻只有一个权威写入者；多个客户端同时发请求时，服务器确定结果与顺序。

## 4. 需要保存的数据

| 对象 | 至少包含 |
| --- | --- |
| 玩家 | playerId、外观、背包版本、当前位置、主星地址、授权关系 |
| 星球 | planetId、生成种子、生成器版本、尺度档、环境参数、归属版本 |
| 区块 | 坐标/球面面标识、基础生成信息、修改版本、建筑与资源变化 |
| 建筑 | entityId、部件类型、位置/朝向、所有权、库存引用、状态版本 |
| 操作 | operationId、发起者、状态、结果；用于安全重试 |
| 跨区转移 | transferId、来源、目的地、物品/实体清单、确认状态 |
| 公共工程 | projectId、阶段、材料余额、贡献操作与完成状态 |

基础地貌采用种子与生成器版本重建，保存玩家修改。已发现星球更新生成器时不得静默改变地貌或吞掉建筑；需要明确迁移策略或保留旧版本支持。持久存储仍随玩家改造和探索量增长，不能按“仅存一个种子”估算整体成本。

## 5. 跨区与跨星球转移

原型优先通过星门切换场景，过程显示明确状态。物理上无缝穿越两个模拟区不是首版完成标准。

转移先确认目的地容量和权限，再建立持久转移记录并暂时锁定迁移物品；目标接收成功后，来源完成退出。失败或超时按记录恢复到确定的一侧，重复请求返回同一结果。物品不能在两边都可使用，也不能两边都消失。

源与目标同时崩溃、玩家重连、确认消息丢失、重复请求都是必须覆盖的验收场景。具体存储事务方案在实现阶段确定，不能仅靠客户端请求顺序保证一致性。

## 6. 同步与负载

按距离、可见区域和交互关系订阅动态对象；星图、远处工程进度和离线通知使用低频状态更新。客户端移动可做预测与插值，物品、归属、贡献和建筑位置以服务端确认结果为准。

草木装饰、远景灯光、部分粒子可客户端表现；可采物、碰撞、交互设施和库存有权威状态。建筑数量、活跃机器和同步实体数应与玩家人数一起记录，避免只用空场景容量宣传性能。

## 7. 无人区域与离线结算

无人区域释放高频模拟，保留最后结算时间、输入原料、生产状态和仓储容量。恢复时计算受资源与容量约束的产量；满仓后停止，不产生物资无限累积。

结算依据服务端时间，客户端时间变化不产生收益。多次唤醒或重试不得重复结算。朋友进入会唤醒被授权的星球，不要求主人上线。

## 8. 权限与合作

权限按“星球/区域/设施 × 操作”表达：访问、放置、移动、拆除、取出、存入和管理可分别授权。角色只是权限集合的快捷方式，服务端每次执行关键操作时检查当前权限。

撤销权限后，尚未确认的新操作应被拒绝；已确认成果仍保留。库存和公共项目的变更保留可追踪记录。断线不自动把协作者提升为所有者。

## 9. 热点接待

热门工程可分为多个实际施工区域，进度统一汇总；独立探索活动可使用明确标识的独立场景。私人家园保持唯一建设状态，不通过创建多份可独立修改的同名星球接待超量玩家。

实时区域满载时显示等待/改去相邻会客地点的选择，并尽量保持同行者一起进入。相邻分区不能解决所有人聚集在同一个交互点的计算瓶颈。人数限制、机器数限制和容量提示必须依据实测制定。

## 10. 第一轮工程验收

- 两名玩家同时访问同一建筑，看到相同位置、状态和库存。
- 同一材料被同时请求用于建造与赠送时，只允许合法的一次消费。
- 重复提交项目贡献不重复扣除物品、不重复增加进度。
- 跨星球过程中断线，重连后人和物品归属唯一。
- 无人区域结算不重复、满仓不超产、资源不足不负数。
- 主人离线，协作者可以按授权访问和建造；撤权后关键操作被拒绝。
- 重启服务后归属、建筑、发现与项目状态恢复。
- 种子与生成器版本重现既有基础地貌，保存的修改正确覆盖。

容量报告必须注明硬件、网络、版本、区域数量、活跃玩家、每区实体/建筑/机器、延迟分位数、带宽、内存和故障率。具体阈值在技术样区确定后记录。
